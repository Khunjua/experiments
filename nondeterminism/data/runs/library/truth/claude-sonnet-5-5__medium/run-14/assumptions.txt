- Unknown member or book IDs make any action fail with { ok: false }; getMember for an unknown member returns { ok: false }.
- Adding a duplicate book or member is refused and changes nothing.
- Expired set-aside periods are processed lazily at the start of every call, using that call's date. A set-aside is expired when the call date is after readyUntil, so readyUntil itself is still valid.
- If several set-aside periods have lapsed, they are processed in a chain. Each next member gets the old readyUntil + 3, not a date counted from the current call.
- A member who is set aside a book can still borrow it even if their loan count or owed amount would block a normal borrow? No: the loan limit (5) and the fine limit (1000 or more owed) still apply, and the hold stays in place if the borrow is refused.
- A book set aside for a member cannot be borrowed by anyone else, including a member who has no hold.
- A hold on a book set aside for someone else is allowed and joins the end of the line. A member can hold a book that is set aside for another member if they are not already in the line.
- The member at position 1 of a set-aside book shows its readyUntil. All other holds show null.
- Renewal is not blocked by the amount owed, and it is not blocked by the set-aside state, since a book on loan has no set-aside state.
- A fine is charged at return time and added to owed even if that pushes the member over 1000. The late-day count is return date minus due date, and a fine applies only from 3 days late (25 × days late, capped at 500).
- payFine requires an integer amount, greater than 0 and no more than owed. Paying when nothing is owed is refused.
- A refused action never changes state, apart from the date-driven expiry of set-asides, which happens regardless.

- Calendar validity uses proleptic Gregorian rules, so year 0000 is treated as a leap year; dates are compared as strings after validation.
- A non-object argument (missing, null, primitive) is treated as an empty object, so the call fails as invalid input.
- Any unexpected internal exception is caught and reported as `{ ok: false, reason: 'internal' }`; no state change is intended on that path.
- Failure reasons are short descriptive strings; the spec says callers ignore them.
- Hold expiry (advance) runs after the argument-shape check and before business rules in every dated method, including getMember and payFine, and also when the call later fails.
- Each book keeps a `loanedTo` member reference alongside its status so a return can confirm the borrower without scanning all members.
- Each member keeps its active hold book IDs in placement order, which is used for the `holds` output order and removed when a hold is picked up or expires.
- A pickup removes only the set-aside first entry; the remaining waiting entries keep their order and the book stays `loaned` with that queue intact.
- A return with a non-empty queue sets the first waiting entry as set aside from the return date through date + 6 days, following the spec's rule.
- Overdue means `dueDate < date` strictly; a loan due on the given date is not overdue.
- A member with a loan of a book whose status is `reserved` for them cannot exist as a separate state; the book-status check order follows the spec's numbered rules exactly.
- Loans are returned by `getMember` in array (creation) order, which matches the spec's oldest-first requirement.
- The `position` for a set-aside member is 1 and `readyUntil` is null for every waiting hold.
- `amount` values such as `0`, negative numbers, non-integers and `NaN` are all rejected by `payFine`.
- `bookId` and `memberId` are accepted as any non-empty string, including whitespace-only strings, with no trimming.
- Extra fields in input objects are ignored, and success results contain only the fields listed in the interface.
- Advance processes books in Map insertion order; because books are independent, the order does not change the result.
- Renewal is refused when the loan's due date has passed (`date > dueDate`) but allowed on the due date itself.
- Returning a book when no loan exists for that member and book is a failure with no state change.
- `FINE_PER_DAY`, `GRACE_DAYS`, `MAX_FINE_PER_LOAN` and the other policy constants are applied exactly as stated in section 2.

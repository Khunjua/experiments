- Loan period is 21 days counted from the borrow date; the due date is borrow date plus 21 days.
- A renewal gives 21 days counted from the renewal date, not from the old due date.
- A member may renew at most 2 times per loan.
- Renewal is refused if any hold is waiting on the book, if the loan is already overdue, or if the renewal date is after the due date. Renewal on the due date itself is allowed.
- Late fine: returns up to 3 days after the due date are free; each day beyond that costs 25 cents; the fine per return is capped at 500 cents.
- Fines are added to the member's owed balance at the time of return.
- A return by someone other than the borrower, or of a book not on loan, returns { ok: false, fine: 0 } and changes nothing.
- When a book is returned and holds exist, the first hold in line is set aside for pickup until the return date plus 3 days.
- If a set-aside hold is not picked up by its last day, it expires; the next person in line is set aside from the day after expiry, with the same 3-day pickup window.
- Only the first person in the line has a non-null readyUntil; others have null. Position 1 means the next in line, including a person whose book is set aside for them.
- A set-aside book can only be borrowed by the member it is set aside for; that borrow consumes the hold.
- Holds can only be placed on books currently on loan; a member cannot hold a book they have on loan or hold it twice.
- There is no limit on the number of loans or holds a member may have.
- Members with an outstanding balance are not blocked from borrowing, holding, or renewing, because the requirements did not say so.
- A book already on loan cannot be borrowed again.
- payFine accepts only a positive integer amount that does not exceed the amount owed; overpayments are rejected and no change is given.
- getMember for an unknown member returns an empty result ({ loans: [], owed: 0, holds: [] }) rather than { ok: false }, because the interface defines that return shape.
- Loans in getMember are listed in the order the books were added.
- Duplicate addBook or addMember calls return { ok: false }.
- Expiry of set-aside holds is evaluated lazily on every call using that call's date, which is safe because calls arrive in date order.
- IDs are assumed to be valid strings and dates are assumed to be valid 'YYYY-MM-DD' strings; no further input validation is performed.
